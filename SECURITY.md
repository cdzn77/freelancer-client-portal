# Security reports

Do not post credentials, client content, or exploit details in a public issue. Use GitHub's private vulnerability reporting for this repository when available. If it is unavailable, open an issue asking the maintainer for a private reporting channel without disclosing the vulnerability.

Each operator is responsible for their deployment, backups, provider accounts, and access policies. Keep the Supabase service-role key server-side, use a separate database for tests, and review guest visibility before sharing real work.

Automated permission checks are included. They do not constitute a security certification or a complete manual audit.
